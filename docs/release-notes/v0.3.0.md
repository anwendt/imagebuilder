# imagebuilder v0.3.0

## Highlights

- Added ADR-003 aligned restartable provisioner init containers for provisioners that should run outside the main builder process.
- Added remote-build E2E coverage for marketplace-style Linux image sources across Azure, AWS, OpenStack/Open Telekom Cloud, and vSphere.
- Added architecture workflow and use-case Mermaid diagrams.
- Hardened provisioner workspace file access to satisfy the required security gates.
- Updated chart, provider, and default image versions for the v0.3.0 release line.

## Provisioning

- Ansible, Chef, Puppet, SaltStack, and custom provisioners can now be launched as Kubernetes init containers.
- The builder writes per-step provisioner input into the shared workspace and waits for each init container to write a status document.
- Provisioner config and status paths are constrained to `/workspace` to prevent accidental or malicious path traversal.

## Provider And E2E Changes

- Azure, AWS, OpenStack/Open Telekom Cloud, and vSphere E2E coverage now includes Ubuntu 24.04 latest-style marketplace examples.
- The marketplace image examples remain provider-neutral; Ubuntu 24.04 is the shipped sample workload, not a hard-coded source model.
- vSphere examples support Content Library based source selection.

## Documentation

- Added `docs/architecture/diagrams.md` with workflow and use-case diagrams.
- Replaced the high-level component diagram with Mermaid to avoid Markdown preview alignment issues.
- Cleaned up licensing and architecture documentation to match the current implementation.

## Security

- Fixed `gosec` G304 findings by reading provisioner files through `os.OpenRoot`.
- Added unit coverage for provisioner workspace path validation.
- Required Security Gates are green for `go vet`, `staticcheck`, `gosec`, `govulncheck`, and license checks.
